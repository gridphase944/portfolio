# MNIST型 AI-OCR

> **Historical Project / 開発時期：2024年1月頃**

証券ソフトの画面に表示される板情報などの数値を取得するために作成した、実画面向けのOCRシステムです。

個人開発したHistorical Projectで、OpenCVによる画像前処理、画面レイアウトを利用した座標管理、TensorFlow / Kerasによる文字分類、CPU並列処理などを組み合わせています。

このProjectの中心は高性能なOCRモデルそのものではなく、**固定レイアウトの実画面から必要な領域を切り出し、分類モデルへ入力できる形へ変換し、数値データとして取得するpipelineを構築したこと**です。

## 開発背景

当時開発していたDQNによる株式売買判断モデルへ入力するため、証券ソフトの画面に表示される板情報などを数値データとして取得する必要がありました。

そこで、

1. 画面上の対象セルの位置を登録
2. スクリーンショットから対象セルを切り出す
3. OpenCVで文字領域を抽出・整形
4. 1文字単位で分類モデルへ入力
5. 認識した文字を数値へ復元
6. 後段で利用できるNumPy配列として保存

という処理を実装しました。

対象画面は固定的な表レイアウトであったため、汎用OCRとして未知のレイアウトを認識させるのではなく、**画面構造を利用して対象領域を先に限定する設計**としています。

## 座標登録

OCR対象となる画面は表形式で構成されているため、セルの境界をあらかじめ登録し、OCR時に再利用します。

`coordinate_registration.py` から `OCRST.GetCoordinate()` を呼び出し、OpenCVのマウス操作を使って、

- 各項目の左右のX境界
- 各行のY境界

を登録します。

登録したX・Y境界から各セルを、

```text
[x1, y1, x2, y2]
```

の形式へ変換し、概ね次のshapeを持つNumPy配列として保存します。

```text
(項目数, 行数, 4)
```

これにより、OCR実行時に毎回セル位置を画像処理で検出するのではなく、登録済み座標を使って対象領域を直接切り出せるようにしています。

複数の実行環境で画面位置に差があったため、エピソード名に含めた内部管理ラベルに応じて使用する座標セットを切り替える処理も実装しています。

## OpenCVによるOCR前処理

文字認識の中心処理は `OCRST.output_ocr()` にあります。

### 1. セルの切り出し

登録済み座標を使用して、表の1セル単位で画像をcropします。

罫線を文字として誤検出しないよう、登録したセル境界より数ピクセル内側を使用しています。

### 2. 二値化

カラー画像をグレースケール化し、固定閾値で二値化します。

対象は同じ証券ソフト上の固定された表示条件であり、汎用的な画像への対応よりも対象画面に合わせた処理を優先しています。

### 3. contourによる文字抽出

セル画像を拡大した上で輪郭を検出し、それぞれの輪郭からbounding boxを取得します。

bounding boxをX座標順に並べることで、複数桁の数字を左から順番に処理します。

### 4. 接触した文字への対応

複数文字が1つの大きな輪郭として検出される場合があったため、輪郭の幅から複数文字と判断し、文字画像を再分割する処理を入れています。

これは対象ソフトの表示フォント・画面条件に合わせたヒューリスティックな処理です。

### 5. モデル入力への変換

切り出した1文字画像へ余白を追加し、

```text
21 × 20
```

へresizeした後、画素値を0〜1へ正規化して分類モデルへ入力します。

## 文字分類モデル

学習済みモデルのHDF5メタデータから、使用していたモデルは次の構成であることを確認しています。

```text
Input: 21 × 20
  ↓
Flatten
  ↓
Dense 128 / ReLU
  ↓
Dropout 0.2
  ↓
Dense 11 / Softmax
```

CNNではなく、Flattenと全結合層を使用したシンプルなKeras Sequentialモデルです。

出力11クラスは、

- `0`〜`9`：数字
- `10`：小数点

に対応します。

モデル自体の高度化を目的にしたProjectではなく、**限定された実画面の文字を識別し、前後の画像処理・データ処理へ接続するための分類器**として使用しました。

### 学習データ

学習データは、実際の画面画像から文字を1文字単位へ切り出して作成しました。

当時は、

1. 元画像から文字候補を1文字ずつ切り出す
2. OCR実行時と同系統の前処理を行う
3. 切り出した画像を一旦保存
4. 自作のラベリングツールで画像を表示
5. キーボードから正解ラベルを入力
6. ラベルに対応するフォルダへ画像を振り分ける

という流れでデータセットを作成していました。

現在残っているデータセットでは、`0`〜`9`と小数点の計11クラスを確認しています。

対象は同じソフトウェア・同じ表示条件の文字であり、未知フォントや一般画像に対する汎化性能を目的としたOCRではありません。

そのため、このProjectではモデルのaccuracyを主要な成果として扱っていません。

## 黄色セルによる現在値位置の検出

板画面では、現在値に対応するセルが色で強調表示されていました。

この位置は数字OCRとは別に、`OCRST.PositionInvestigation()` で色から検出します。

数字OCRでは二値化画像を使用しますが、色判定には色情報が必要なため、

- 数字認識：二値化した画像
- 現在値位置：フルカラー画像

を使い分けています。

カラー画像をHSVへ変換し、対象色のマスクから最大輪郭を取得します。その輪郭のY方向の重心がどの価格行に含まれるかを確認することで、現在値の行位置を求めます。

OCRモデルだけですべてを認識するのではなく、**画面UIが持つ色情報も組み合わせて必要な状態を取得する設計**としました。

## 1画面から2銘柄を処理

当時は1920×1080の1画面上に、左右それぞれ別の銘柄の情報を配置していました。

```text
1920 × 1080

┌──────────────┬──────────────┐
│   左側 960px   │   右側 960px   │
│     銘柄A      │     銘柄B      │
└──────────────┴──────────────┘
```

OCR時には左右をそれぞれ960×1080へcropします。

crop後は左右ともX座標が0から始まるため、同じ形式のローカル座標データを両側へ適用できます。

## CPUによる並列OCR

当時はAWS EC2上のCPU環境でOCRを実行していました。

GPUを利用したOCR環境ではなかったため、処理時間短縮を目的としてPythonの`multiprocessing`を使用しています。

`testOCR.py`ではエピソードディレクトリを複数のworkerへ分配し、現在のコードでは4つのプロセスで並列処理します。

```text
Episode 1 ─┐
Episode 2 ─┼─→ Worker 1
Episode 3 ─┤
...        │
           ├─→ Worker 2
           ├─→ Worker 3
           └─→ Worker 4
```

各workerは独立してOCRモデルを読み込み、担当するエピソード内の画像を順番に処理します。

プロセス数は実行環境のCPUコア数等に合わせて手動で調整する想定でした。

当時の速度比較結果は残っていないため、並列化による具体的な高速化率は記載していません。

## 入出力

### 入力

`testOCR.py`では、`OCR_result/`以下のエピソードディレクトリからJPEG画像を読み込みます。

画像はファイル名中の数字を考慮した自然順で並べ、時系列順に処理します。

### 主なOCR対象

コード上では、以下のような値を取得しています。

- 時刻
- 約定値
- 出来高
- 価格
- 買数量
- 買件数
- 売数量
- 売件数
- 現在値の行位置

### 出力

OCR結果は項目ごとのNumPy配列として保存します。

後段の処理から利用しやすいよう、画像ではなく構造化された数値データへ変換することを目的としています。

| [`OCRST.py`](./OCRST.py) | OpenCV前処理、文字認識、色検出、座標登録などの中心処理 |

## 本人の実装範囲

このProjectでは、本人が中心となって以下を実装しました。

- 実画面に合わせた座標登録処理
- OpenCVによるセル・文字単位の画像前処理
- contour / bounding boxを用いた文字抽出
- 接触文字への対応
- 分類モデルへの入力整形
- OCR結果の数値復元
- 色情報を利用した現在値位置の検出
- multiprocessingによるCPU並列処理
- 学習用文字画像の作成・ラベリングの仕組み
- OCR処理と後段システムを接続するためのデータ出力

文字分類モデルは、高度な独自モデルを設計したものではなく、シンプルなニューラルネットワークを使用しています。
